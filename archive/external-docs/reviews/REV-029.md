## 核心结论（先说重点）
1) demo 的工程化优势明显：Prompt Engine（安全模板子集 + blocks/presets + budget + render_log）、MemoryContextPack、VectorRAG（multi provider + rerank + hybrid）、E2E/contract 测试闭环，是“可控/可回放/可回归”的底座。
2) Amily 的产品化优势明显：多阶段提示词流水线编排（PresetSettings）、最后一刻提示词审查/编辑（密折司 Prompt Inspector）、表格记忆（结构化状态→世界书条目）、RAG（多知识库 + 预处理 + rerank + super sort）、以及“可视化对比”工具（PreOptimizationViewer）。
3) MuMu 的平台化优势明显：多用户/OAuth、章节工作流完善（阅读/分析/一键重写/批量）、向量记忆（Chroma + sentence-transformers）与“智能上下文构建”深度集成到生成链路，并把 MCP 工具调用纳入生成流程（阶段化进度提示与降级）。
4) demo 若要“吸收优点”应坚持：**保留 demo 的安全红线与测试闭环**；迁移 Amily/MuMu 的做法时做“概念迁移”，避免把其实现方式（尤其无测试/弱约束的字符串模板）直接拷贝进来。

## Amily（ST 插件）可迁移“做法”（强调：概念迁移）
### 1) 多阶段流水线与可视化编排
- PresetSettings：提示词链路与条件编排（“混合顺序/条件块”），适合迁移为 demo 的“生成流水线编辑器”（而不是把字符串模板搬过来）。
  - 参考：`Amily/PresetSettings/*`

### 2) Prompt Inspector（密折司）
- 价值：在“请求发送前最后一刻”查看最终 prompt（包含注入/宏展开结果）并允许人工修改，极大提升可控性与可解释性。
  - 参考：`Amily/MiZheSi/index.js`

### 3) 表格记忆（结构化状态→世界书/记忆）
- 价值：把“物品/任务/时间地点/状态”结构化，提供稳定注入与回滚；并通过安全执行器避免模型输出污染。
  - 参考：`Amily/core/table-system/*`、`Amily/core/table-system/executor.js`

### 4) RAG（翰林院）
- 价值：多知识库、多来源分块、检索预处理、rerank、super sort、Graph RAG。
  - 参考：`Amily/core/rag-processor.js`、`Amily/core/super-sorter.js`、`Amily/core/context-optimizer.js`

## MuMu（平台）可迁移“产品形态”
