# REV-017 — docker-compose / Dockerfile / nginx 容器安全 review

## 背景
本条目审计 `docker-compose.yml`、前后端 Dockerfile 与 nginx 反代配置，关注：
- secrets 注入方式与默认值风险
- ports/volumes 的暴露范围
- CORS、worker（RQ）形态是否与部署目标一致

## 检查项
- `env_file` / 环境变量是否会引入敏感信息泄露风险（以及是否易误提交）
- DB/Redis/Backend/Frontend 的端口暴露是否符合“本地开发 vs 生产部署”的预期
- volumes 是否最小化、是否存在将宿主敏感路径挂进容器的风险
- 反代 nginx 的 `/api/` 配置是否合理（Host/Forwarded headers、timeout）
- worker（rq_worker）是否与 backend 共享必要配置（DB/Redis/Chroma）

## 发现点
### 1) docker-compose 形态更偏向“本地单机/内网开发”
- `postgres`/`redis` 都做了 `ports:` 映射到宿主机，默认会绑定到所有网卡（`0.0.0.0`）。
  - 对本机开发便利，但若在公网/不可信网络运行存在暴露风险。
- `backend` 同样映射 `8000` 到宿主机，`frontend` 映射 `5173` 到宿主机（容器内 nginx 80）。
- 关键配置使用 `.env.docker` 注入（需要确保该文件不被提交，并在生产环境替换为更安全的 secrets 管理方案）。

### 2) volumes 使用相对克制
- `postgres_data`：持久化数据库数据
- `chroma_data`：backend 与 worker 共用向量库持久化目录（符合共享需求）
- 未发现将宿主敏感目录（如 `$HOME/.ssh`、源代码目录等）直接挂载进容器的配置

### 3) CORS 与 nginx 反代的组合需要明确部署目标
- compose 中 `CORS_ORIGINS=http://localhost:5173` 适配“前端在宿主机端口 5173 访问后端”的开发场景。
- nginx 反代 `/api/` 到 `backend:8000`，对外仅暴露 frontend 端口时，Origin 可能不再是 `localhost:5173`（生产需按实际域名配置 CORS）。

### 4) Dockerfile：可运行，但生产安全加固空间较大
- `backend/Dockerfile` 以 root 安装依赖与运行（默认），可考虑增加非 root 用户运行以降低风险。
- `frontend/Dockerfile` 最终镜像使用 `nginx:alpine`，同样可按需要切换到更严格的 unprivileged nginx 镜像/用户。

## 证据（命令与关键输出摘要）
- 执行（CSV Test_Method）：
  - `rg -n 'CORS_ORIGINS|SECRET_ENCRYPTION_KEY|TASK_QUEUE_BACKEND|REDIS_URL|ports:|volumes:' docker-compose.yml backend/Dockerfile frontend/Dockerfile frontend/nginx.conf -S`
  - 命中要点：`TASK_QUEUE_BACKEND=rq`、`REDIS_URL=redis://redis:6379/0`、`CORS_ORIGINS=http://localhost:5173`、多处 `ports:`/`volumes:`

## 结论
当前 docker-compose 更偏向本地开发/内网调试形态，结构清晰；若用于生产部署，需补齐“最小暴露面 + secrets 管理 + 非 root 运行”等加固措施。

## 风险与建议
- **高优先级建议（生产部署前）**
  - DB/Redis 不对公网暴露：移除 `ports:` 或绑定到 `127.0.0.1:...`，并使用防火墙/安全组限制访问。
  - secrets 不使用明文 env_file：改用平台 secrets（或至少将 `.env.docker` 严格加入 `.gitignore` 并使用示例模板）。
  - 后端/反代补 TLS、HSTS、必要的安全响应头（按部署域名配置）。
- **中优先级建议**
  - backend/nginx 使用非 root 用户运行（容器内 `USER`），并尽量只读文件系统（需要时为写路径单独挂载 volume）。
  - 明确 CORS_ORIGINS 的生产配置策略（域名列表/通配符策略/凭证 cookie 场景）。
