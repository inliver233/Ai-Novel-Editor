# REV-023 — FractalMemory rebuild 确定性与注入 review

## 背景
FractalMemory 用于将已完成章节压缩为 “scenes → arcs → sagas”，并输出最新 saga 的 `prompt_block.text_md` 作为注入片段。
本条目审计：
- rebuild 的确定性（同输入章节 → 同输出）
- 章节筛选逻辑（status=done）
- `char_limit` 等预算控制
- 路由侧 RBAC（viewer/get、editor/rebuild）
- 测试覆盖缺口与建议

## 检查项
- `compute_fractal` 是否只依赖确定性输入（chapter 字段/排序）
- rebuild 是否固定排序、固定窗口分组（scene_window/arc_window）
- 注入文本是否有 char budget（fractal_char_limit）
- get/rebuild 路由是否按项目权限控制

## 发现点
### 1) rebuild 逻辑确定且可解释
- `rebuild_fractal_memory` 按 `Chapter.number ASC` 读取章节，并在 `compute_fractal` 内仅保留 `status == "done"` 的章节作为输入。
- scenes/arcs/sagas 的分组完全由 `scene_window/arc_window` 决定，且截断逻辑固定（summary/arcs/sagas 各自有上限 + 最终 char_limit）。

### 2) 注入预算控制存在
- arc summary 超过 2000 chars 会截断；saga summary 超过 4000 chars 会截断；最终 `prompt_block` 还会按 `fractal_char_limit` 再截断一次。

### 3) RBAC 合理
- `GET /projects/{project_id}/fractal`：viewer
- `POST /projects/{project_id}/fractal/rebuild`：editor

### 4) 兼容性风险修复：避免使用 Python 3.12+ 的语法
`fractal_memory_service` 中的 `_chunks` 原先使用了 Python 3.12+ 的 PEP 695 语法，可能导致在 Python 3.11 环境（例如容器镜像）下无法导入。
本次已改为 `TypeVar` 写法，保持向后兼容。

## 结论
FractalMemory 的 rebuild 在“章节排序/筛选/窗口分组/截断”层面具备确定性与预算控制；RBAC 配置合理。本次同时消除了潜在的 Python 版本兼容性风险。

## 改进建议（不在本次实现范围内）
- 增加服务层/路由层集成测试覆盖 `rebuild_fractal_memory` 的存取闭环（写入 DB → get_fractal_context）。
- 若未来支持更大规模章节，可增加对 `done` 章节数量的硬上限或增量更新策略（避免全量 rebuild 成本）。
