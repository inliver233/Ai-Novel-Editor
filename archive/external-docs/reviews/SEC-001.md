# SEC-001 - [backend][security] Cookie session CSRF 与 CORS（prod 护栏）再审计

## 背景
本仓库采用 **cookie session（HttpOnly）** 作为登录态，并在后端启用 `CORSMiddleware` 且 `allow_credentials=True`。该组合在 **prod 环境** 一旦出现 CORS 误配置（例如把 `CORS_ORIGINS=*` 放开），可能导致跨站读取/写入风险。

本条目目标：
- 记录当前实现与威胁模型（threat model）
- 给出 prod 推荐配置
- 必要时补充最小“误配置护栏”

## 当前实现（关键代码点）
- CORS：`backend/app/main.py`
  - `CORSMiddleware(allow_credentials=True, allow_origins=settings.cors_origins_list() ...)`
- Session cookie：`backend/app/core/auth_session.py`
  - `secure = APP_ENV == "prod"`
  - `samesite = settings.auth_cookie_samesite`（默认 `lax`）
  - `httponly=True`
- 配置：`backend/app/core/config.py`
  - `cors_origins` 默认 `http://localhost:5173`
  - `auth_cookie_samesite` 默认 `lax`

## Threat model（简化）
攻击者能力假设：
- 攻击者可控制一个第三方站点（例如 `evil.example`），诱导用户访问
- 用户已在本系统登录（浏览器已存有 session cookie）

主要风险：
1) **CORS 误配 + allow_credentials=True**
   - 若 prod 把 `CORS_ORIGINS` 配成 `*` / `null` / 或包含不可信 origin，则第三方站点可通过 XHR/fetch 携带 cookie 请求后端，并**读取响应内容**。
2) **CSRF（跨站写入）**
   - 在 cookie session 模式下，若 `SameSite=None` 或后端存在可被“简单请求/表单”触发的写接口，则可能产生 CSRF 风险。
   - 当前默认 `SameSite=Lax` 对典型跨站 POST 有一定缓解作用，但并不等同于完整 CSRF 防护（尤其是存在 GET 写入或其它边界时）。
3) **XSS**
   - `HttpOnly` 可降低 cookie 被 JS 直接读取的风险，但 XSS 仍可能代表“同源任意请求能力”，需要与 CSRF/CORS 分开治理。

## prod 推荐配置（建议）
**默认建议（简单且安全）**
- `APP_ENV=prod`
- `CORS_ORIGINS`：仅列出可信前端 origin（建议只包含 HTTPS 的单一/少量域名）；不要写 `*`/`null`
- `auth_cookie_samesite=lax`（默认即可）

**如必须跨站携带 cookie（SameSite=None）**
- 必须保证 HTTPS（浏览器要求 `SameSite=None` 配合 `Secure`）
- `CORS_ORIGINS` 必须精确列出可信前端 origin（不要通配）
- 需要补充 CSRF 防护策略（至少其一）：
  - CSRF token（双提交 cookie / header token）
  - 校验 `Origin`/`Referer`（并明确允许列表）
  - 将关键写接口改为必须携带自定义 header 且拒绝简单请求（仍需谨慎评估）

## 本次最小护栏（避免“误配置即中招”）
- 在 `Settings` 的 prod 校验中，**禁止** `cors_origins` 包含 `*` 或 `null`（降低 allow_credentials 被误配的风险）

## 证据（命令与关键输出摘要）
- 命令：`rg -n \"allow_credentials|auth_cookie_samesite|set_cookie\" backend/app`
  - 命中：
    - `backend/app/main.py`：`allow_credentials=True`
    - `backend/app/core/auth_session.py`：`samesite = settings.auth_cookie_samesite` / `response.set_cookie(...)`
    - `backend/app/core/config.py`：`auth_cookie_samesite` 默认 `lax`

## 结论
当前默认 `SameSite=Lax` + prod `Secure` cookie 属于相对稳妥的默认组合；主要风险来自 **prod CORS_ORIGINS 误配置**。本条目以文档 + 最小校验护栏降低误配风险，并将“跨站 cookie（SameSite=None）时的 CSRF 策略”作为明确的后续配置要求。
