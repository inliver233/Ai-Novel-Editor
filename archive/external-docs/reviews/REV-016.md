# REV-016 — project_memberships / require_project_access 集成 review

## 背景
后端以 `projects.owner_user_id` + `project_memberships.role` 实现项目级 RBAC，并通过 `require_project_viewer/editor/owner` 在各路由处做访问控制。

本条目审计：
- `require_project_access` 的角色判定与边界（owner/membership/非法 role）
- `backend/app/api/routes/*` 中 viewer/editor/owner 的覆盖情况（给出矩阵/缺口）
- 补足关键测试，防止未来回归

## 检查项
- 角色判定：
  - owner 是否优先于 membership
  - membership.role 是否做 trim/lower（避免脏数据导致误判）
  - 非法 role 是否 fail-closed（默认拒绝）
- 路由覆盖：
  - 读接口是否至少 viewer
  - 写接口是否至少 editor
  - 危险操作（如删除项目）是否 owner
- 测试覆盖：
  - viewer/editor/owner 的基本能力边界
  - role 解析的健壮性（大小写/空格）

## 发现点
### 1) require_project_access 逻辑清晰且 fail-closed
- owner：`project.owner_user_id == user_id` → `owner`
- member：读取 `ProjectMembership(project_id,user_id)`，对 `role` 做 `strip().lower()`，仅允许 `viewer/editor/owner`
- 非 member 或非法 role → `FORBIDDEN`
- `_ROLE_RANK` 用于比较最小权限（viewer < editor < owner）

### 2) 路由角色覆盖（抽样矩阵）
（按代码静态扫描 `backend/app/api/routes/*` 得到，列出代表性入口）
- `projects.py`
  - `GET /projects/{project_id}`：viewer
  - `PUT /projects/{project_id}`：owner
  - `DELETE /projects/{project_id}`：owner
- `chapters.py`：列表/读取 viewer；创建/更新 editor
- `outline.py` / `outlines.py`：读取 viewer；创建/更新 editor
- `characters.py`：读取 viewer；创建/更新 editor
- `worldbook.py`：读取 viewer；创建/更新 editor
- `settings.py`：`GET` viewer；`PUT` editor
- `memory.py`：retrieve/structured 等 reader 侧多为 viewer；apply/rollback 等写侧为 editor
- `vector.py`：rebuild/ingest/query 等按用途区分 viewer/editor（写侧为 editor）

未发现“明显缺失 RBAC 检查的路由”（即：在拿到 project_id 后未调用任何 require_project_* 直接读写资源）的情况。
