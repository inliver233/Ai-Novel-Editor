# REV-008 — [data][sqlite] 单 worker 与 LLM 调用事务边界审计

## 背景
- SQLite 在多 worker/长事务场景容易出现 `database is locked`；本项目约束为 **SQLite 单 worker**。
- LLM 调用（外部网络 + 流式）是典型长耗时操作，必须避免持有 DB 会话/事务跨越 LLM 调用窗口。

## 检查项
- SQLite 单 worker 约束是否在代码与文档中一致且可见。
- 关键生成链路（outline/chapter/analyze/rewrite/stream）是否做到：
  - DB 读取/提示词渲染：短 session
  - LLM 调用：不持有 session/事务
  - 落库（generation_run 等）：独立短 session

## 调用链（简图）
- 非流式（outline generate / chapter_analyze / chapter_rewrite 等）：
  1) route: `SessionLocal()` 读取 project/chapter/preset + render prompt
  2) `db.close()`（结束请求侧 session）
  3) `call_llm_and_record(...)` → `call_llm(...)`（LLM 调用，无 DB session 依赖）
  4) `write_generation_run(...)`（`run_store.py` 内部 `with SessionLocal()` 独立落库）

- 流式（chapter_generate-stream / outline_generate-stream）：
  1) route: `SessionLocal()` 读取数据 + render prompt
  2) `db.close()`
  3) `call_llm_stream_messages(...)`（流式迭代）
  4) 结束后通过 `write_generation_run(...)` 独立短 session 记录结果/错误

## 发现点
1) SQLite 单 worker 约束在代码与 README 中一致
- `backend/app/main.py::_warn_sqlite_single_worker()`：SQLite 模式启动时输出 warning，提示 `--workers 1`。
- 根 `README.md` “SQLite 约束（MVP 口径）”明确单 worker 约束与“LLM 调用不得持有长事务”。

2) 关键 LLM 调用链路未持有请求侧 DB session（符合约束）
- `backend/app/api/routes/chapter_analysis.py`：在调用 `call_llm_and_record(...)` 前已 `db.close()`。
- `backend/app/services/generation_pipeline.py::run_post_edit_step`：在调用 `call_llm_and_record(...)` 前结束 `with SessionLocal()`。
- `backend/app/api/routes/chapters.py` 流式生成：准备阶段结束后 `db.close()`，随后才进入 `call_llm_stream_messages(...)`。

3) generation_run 落库使用独立短 session
- `backend/app/services/run_store.py::write_generation_run()` 使用 `with SessionLocal()` 单独落库，避免与请求生命周期耦合。

## 证据（命令与关键输出摘要）
- `rg -n "SessionLocal\\(|with SessionLocal\\(|call_llm|call_llm_and_record" backend/app/api/routes backend/app/services -S`
  - 命中：routes 侧准备阶段 `SessionLocal()`、服务侧 `call_llm_and_record`、`run_store.py` 独立 session。

## 结论
- 当前关键生成链路符合 “LLM 调用不持有长事务” 的约束；SQLite 单 worker 约束在代码与文档中一致。
- 本次无需代码修复。
