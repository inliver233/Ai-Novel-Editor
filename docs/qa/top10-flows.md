# Top 10 必不破坏工作流（手工回归清单）

> 目标：在重构期间，确保用户核心写作体验不回归。  
> 使用方式：按本文逐条执行，每条都要留下证据（截图/日志/输出）。

## 运行前准备
- 需要 1 个可用项目（包含 `project.db` / `vectors.db`，或应用当前实现使用的数据文件）。
- 建议开启日志输出（如有），并记录测试日期与环境信息。
- 准备 1 份可导入样例（至少一个 `txt`；如支持也可准备 `docx`）。

## 证据规范（最小要求）
- 每条工作流至少提供一种证据：
  - 截图（界面关键状态）
  - 日志片段（关键操作完成/异常为空）
  - 导出文件/输出（如导出/备份/恢复等）
- 建议统一存放到本地 `screenshots/qa/<date>/`（该目录按仓库规则可不提交）。

## Top 10 工作流列表（待细化）

1. **项目：创建/打开项目**
   - Steps:
     1) 启动应用。
     2) 新建一个空项目（或打开已有项目）。
     3) 进入主界面后，确认可正常看到项目内容（如文档列表/编辑器/大纲等）。
     4) 关闭应用后再次启动，重新打开同一项目。
   - Expected:
     - 无崩溃/无卡死；不会出现“项目无法打开/数据库损坏”等错误。
     - 重复打开同一项目不会产生明显重复任务（如重复索引/重复后台任务导致 UI 卡顿）。
   - Evidence:
     - 截图：主窗口显示项目已打开（包含项目名/路径可打码）。
     - （如有）日志：包含 “open project / load project” 成功的关键日志或无异常堆栈。

2. **写作：打开文档并编辑/保存**
   - Steps:
     1) 在项目内打开一篇已有文档；或新建一篇文档并打开。
     2) 在编辑器中输入一段文本（至少 3 行，含中英文/标点）。
     3) 执行保存（如支持 `Ctrl+S` / 菜单保存）。
     4) 切换到另一篇文档再切回，确认文本仍存在。
     5) 重启应用并重新打开该项目与该文档，确认内容持久化。
   - Expected:
     - 保存成功且内容不丢失；切换/重启后内容一致。
     - 无异常弹窗；保存不会导致明显 UI 冻结。
   - Evidence:
     - 截图：保存后文档内容可见（可打码）。
     - （如有）日志：包含保存成功或无异常堆栈。

3. **写作：大纲面板（解析/刷新/跳转）**
   - Steps:
     1) 在当前文档中输入可被识别为标题/章节的结构（例如：`# 第一章`、`## 场景 1` 等）。
     2) 触发大纲刷新（自动或手动刷新均可）。
     3) 在大纲面板中点击某一条目，验证编辑器光标/视图跳转到对应位置。
     4) 修改标题文本后再次刷新，确认大纲同步更新。
   - Expected:
     - 大纲条目数量与层级结构正确；点击跳转正确。
     - 刷新后不出现重复条目/错位条目。
   - Evidence:
     - 截图：大纲面板展示层级结构 + 编辑器对应标题位置。

4. **AI：基础对话/补全（可用性与不阻塞 UI）**
   - Steps:
     1) 打开 AI 配置（如存在统一配置/设置对话框），选择一个 provider 并填写必要配置（如 API Key；可用测试 Key 或 mock 配置）。
     2) 在编辑器中触发一次 AI 补全/对话请求（最小输入即可）。
     3) 在请求过程中尝试：继续点击 UI（切换面板/移动光标/滚动）确认不卡死。
     4) 若支持取消：执行取消（如 Esc/取消按钮），确认 UI 状态复位。
     5) 若未配置 Key：验证错误提示友好且不会破坏编辑器内容。
   - Expected:
     - UI 始终可响应；取消/超时/错误后不会残留“幽灵文本/黄色条”等异常状态。
     - 错误提示清晰，不会导致项目数据损坏/文档内容丢失。
   - Evidence:
     - 截图：AI 面板/提示状态（成功结果或错误提示均可）。
     - （如有）日志：包含请求开始/结束/取消（或错误）记录。

5. **Codex：打开/运行一次核心流程（不崩溃/不丢状态）**
   - Steps:
     1) 打开 Codex 面板/功能入口（如果存在独立 Tab/面板）。
     2) 执行一次最小流程（例如：生成/分析/插入到编辑器）。
     3) 关闭面板再打开，确认状态不异常（不会重复初始化导致报错）。
   - Expected:
     - 不崩溃；执行后有可观测结果（输出/插入/日志）。
     - 面板可重复打开使用；不会出现状态错乱或卡死。
   - Evidence:
     - 截图：Codex 面板输出/结果（可打码）。

6. **RAG：建立索引/检索一次（或使用现有索引）**
   - Steps:
     1) 打开 RAG/索引相关配置或入口（如果存在）。
     2) 对当前项目执行一次“建立索引/更新索引”（或使用已有索引）。
     3) 发起一次检索/查询（用项目中真实出现过的关键词）。
   - Expected:
     - 索引任务可完成或可取消；不会导致 UI 长时间冻结。
     - 检索返回可解释结果（至少不为空/不报错）。
   - Evidence:
     - 截图：索引完成状态或检索结果列表。
     - （如有）日志：包含索引开始/完成/取消记录。

7. **导入：导入文档/项目（含失败保护）**
   - Steps:
     1) 准备一个可导入文件（如 `txt`/`docx`；以实际支持格式为准）。
     2) 在应用中执行导入，导入到当前项目（或新项目）。
     3) 验证导入后的内容能被打开并正常显示。
     4) 失败路径：用一个不支持/损坏的文件触发导入失败，确认不会破坏现有项目数据。
   - Expected:
     - 成功导入：内容完整且可编辑；导入后项目仍可正常保存/打开。
     - 失败导入：有清晰错误提示；不会导致已存在文档/数据库被破坏。
   - Evidence:
     - 截图：导入成功后的文档内容；失败时的错误提示。

8. **导出：导出文档（格式/内容一致性）**
   - Steps:
     1) 选择一篇包含多段落/标题的文档。
     2) 执行导出到一种格式（如 `txt`/`docx`/`pdf`；以实际支持为准）。
     3) 打开导出文件，快速核对：段落分隔、标题、关键文本是否存在。
   - Expected:
     - 导出文件可打开且非空；核心内容一致（允许格式差异）。
     - 导出失败时有提示，且不会破坏项目数据。
   - Evidence:
     - 导出文件路径 + 截图（打开文件后的关键页/关键段落）。

9. **查找替换：基本查找/替换（含边界条件）**
   - Steps:
     1) 在当前文档中插入一个可重复出现的短词（例如：`TEST_WORD` 出现 5 次）。
     2) 打开查找，定位到第 1 处与第 N 处。
     3) 执行“替换下一处” 1 次，再执行“全部替换”。
     4) 撤销/重做（如支持）验证替换可回滚。
   - Expected:
     - 查找定位正确；替换结果正确；撤销/重做行为正确。
     - 不会出现光标错乱/文本重复插入/编辑器卡死。
   - Evidence:
     - 截图：替换前后对比（同一段落即可）。

10. **主题/设置：切换主题或关键设置后重启仍生效**
    - Steps:
      1) 打开设置/主题入口，切换一次主题或一个关键设置（如自动补全开关/字体大小等）。
      2) 关闭并重启应用。
      3) 再次打开设置，确认刚才的设置仍然生效。
    - Expected:
      - 设置可持久化；重启后仍保持；不会引发 UI 渲染异常。
    - Evidence:
      - 截图：设置项在重启前后保持一致（可打码）。
