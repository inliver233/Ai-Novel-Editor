# ANE-0178 — 迁移策略（默认）

目标：从旧版“全局 vectors.db”迁移到 Phase 1 的“每项目独立 vectors.db”，并避免跨项目检索泄露。

## 现状与目标
- 现状（legacy）：全局向量库路径为 `~/.ai-novel-editor/vector_store/vectors.db`（见 `docs/reviews/ANE-0179.md`）。
- 目标（Phase 1 默认）：项目打开后向量库路径解析为 `<project_path>/.rag/vectors.db`（由 `core.vector_store_paths` 统一）。

## 首次切换策略（A/B/C）
触发条件：打开项目时检测到
1) 目标 per-project `vectors.db` 不存在
2) 旧全局库存在且包含 embeddings（`document_embeddings` 行数 > 0）

弹窗提供 3 个选项（Phase 1）：
- A（默认/推荐）：重建索引（后台 `rag/rebuild` 任务，可取消）。
- B：暂不重建并禁用 RAG（不做检索/不做索引，避免继续使用旧全局库）。
- C：尝试迁移 —— Phase 1 置灰；仅当“方案 B（表内 project_id 过滤）”落地后才允许启用。

实现位置：
- `src/gui/services/index_scheduler.py`：在 `Shared.projectChanged` 触发时执行上述检测与弹窗，并根据选择设置 `shared.vector_store` / `shared.rag_service` 的工作模式。

## 不兼容提示
当 per-project 向量库元数据与当前 RAG 配置不兼容时：
- 弹窗提示重建索引（后台可取消），或选择禁用 RAG。

实现位置：
- `src/gui/services/index_scheduler.py`：比较 `vector_store.get_store_metadata()` 与 `rag_service` 的 `embedding_model/chunk_size/chunk_overlap/chunker_version`。
