# REV-006 — [security][xss] 前端 Markdown 渲染与注入预览 XSS 审计

## 背景
- 前端展示 Markdown/富文本时，如允许原始 HTML 渲染或使用 `dangerouslySetInnerHTML`，可能导致存储型/反射型 XSS。
- 本项审计范围：`frontend/src` 内 Markdown 渲染与“预览/Prompt Studio”等可能展示用户输入内容的页面/组件。

## 检查项
- 是否存在 `dangerouslySetInnerHTML` / `innerHTML` 直接注入。
- 是否使用 `react-markdown`/`marked` 并启用 raw HTML（如 `rehypeRaw`）或缺少 sanitize。
- 预览页、编辑器预览、Prompt Studio 等路径是否会把用户可控内容当 HTML 执行。

## 扫描结果
- 全仓（frontend）关键字扫描：
  - 未发现 `dangerouslySetInnerHTML` / `innerHTML` / `marked` 的使用。
  - 发现 `react-markdown` 使用点：
    - `frontend/src/components/atelier/MarkdownEditor.tsx`
    - `frontend/src/pages/PreviewPage.tsx`

## 发现点
1) Markdown 渲染使用 `react-markdown` + `remark-gfm`，未启用 raw HTML
- `MarkdownEditor` 与 `PreviewPage` 均仅配置 `remarkPlugins={[remarkGfm]}`；
- 未见 `rehypeRaw` / 直接 HTML 注入逻辑，因此 Markdown 中的原始 HTML 不会被当作可执行 DOM 注入（默认行为为跳过/转义）。

2) “sanitize” 命中为文件名清理/后端 post_edit 开关，不属于前端 HTML sanitize
- `sanitizeFilename(...)` 用于下载文件名安全化（与 XSS 无直接关系）。
- `post_edit_sanitize` 为生成管线参数开关（后端语义），不等同于前端 DOM sanitize。

## 证据（命令与关键输出摘要）
- `rg -n "dangerouslySetInnerHTML|innerHTML|react-markdown|marked|sanitize" frontend/src -S`
  - 命中：`ReactMarkdown`（编辑器预览、章节预览）
  - 未命中：`dangerouslySetInnerHTML` / `innerHTML` / `marked`

## 结论
- 当前前端 Markdown 展示路径未发现明显 XSS 注入点；实现整体偏“默认安全”。

## 修复方案（建议）
- 保持现状：**不要**在 `react-markdown` 中引入 `rehypeRaw`，除非同时引入并严格配置 `rehype-sanitize`。
- 如后续确需渲染 HTML 子集：建议明确一份 allowlist sanitize 配置，并为典型 payload（`<script>`, `onerror`, `javascript:`）补 E2E 断言。

## 测试结果
- 本 issue 未改动代码，按 `Test_Method` 完成扫描与人工 review；未新增/运行额外 E2E。
