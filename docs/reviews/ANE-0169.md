# ANE-0169 — [EPIC 4.1] SQLiteVectorStore 回归“纯存储/纯检索”

## 目标
- 把“关键词提取/查询规划”从存储层移出（放到 application 层）。
- `SQLiteVectorStore` 仅做“纯存储/纯检索”：接收 **query embedding** 或 **SQL LIKE tokens**，返回候选 chunks。

## 主要改动（落点）
- application：新增 `RAGQueryPlanner`（LIKE tokens 规划）。  
  - `src/application/rag_query_planner.py`
- core：`SQLiteVectorStore.similarity_search_ultra_fast()` 改为 token-only 的 LIKE 检索，返回候选 chunks（dict 列表）。  
  - `src/core/sqlite_vector_store.py`
- core：`RAGService` 新增 `search_with_like_tokens()`，消费候选 chunks 并选择最佳片段；`search_with_context()` 作为兼容入口（单 token）。  
  - `src/core/rag_service.py`
- application：`IntelligentContextBuilder` 在调用 RAG 时先用 `RAGQueryPlanner` 生成 tokens，再调用 `search_with_like_tokens()`。  
  - `src/application/ai_context.py`

## 验收与证据
- 测试：
  - `python -m compileall -q src`
  - `pytest -q`
- 相关 golden/指标覆盖：
  - RAG 查询规划与 overlap 指标测试在 `pytest -q` 中通过（见 `tests/test_golden_rag_query_planning.py`, `tests/test_rag_overlap_metrics.py`）。
