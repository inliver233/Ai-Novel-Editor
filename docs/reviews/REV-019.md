# REV-019 — pgvector hybrid RRF / overfiltering / fallback review

## 背景
pgvector hybrid 检索目标：结合
- 向量相似度（embedding distance）
- 关键词/全文检索（Postgres tsvector + plainto_tsquery）

通过 RRF（Reciprocal Rank Fusion）对两路 rank 做融合，并在“候选过少”时启用 overfiltering（放宽过滤/扩大候选）以避免空检索。

本条目审计：
- RRF 评分实现
- pgvector SQL 参数绑定与查询结构
- overfiltering 策略与 fallback 行为
- 补强单测（不依赖真实 Postgres）

## 检查项
- RRF：
  - rank 越小贡献越大
  - 两路 rank 能累加提升得分
- SQL：
  - 所有用户输入均走参数绑定（query_text/sources/project_id）
  - 过滤条件对 project_id 与 sources 生效
  - details 查询是否仅返回 union id 集合
- overfiltering：
  - union_count < min_needed 时，按策略尝试：relax_sources → expand_candidates
  - 最大尝试次数与最终使用的参数可观测
- fallback：
  - pgvector 异常时回退到 chroma（并可在返回结构中体现）

## 发现点
### 1) RRF 评分实现正确且可复用
- `_rrf_contrib(rank,k)`：`1/(k+rank)`；rank<=0/None → 0
- `_rrf_score(vector_rank,fts_rank,k)`：两路贡献相加

### 2) SQL 参数绑定：关键输入均为 bind params
- `query_text` 以 `:qtext` 绑定，进入 `plainto_tsquery` 与 `ts_rank_cd`
- `query_vec` 转为 `:qvec` 并 cast 为 `vector`
- `project_id` 与 `sources` 在 `WHERE` 条件中使用参数绑定（无字符串拼接用户输入）

注意：`source = ANY(:sources)` / `id = ANY(:ids)` 依赖驱动对 array 参数的适配；若未来遇到类型推断问题，可考虑显式 cast（属于改进项）。

### 3) overfiltering 策略清晰，且产出结构化追踪信息
`_pgvector_hybrid_query` 最多 3 次尝试：
1) 若请求 sources 不是全量 → 先 `relax_sources`（扩大 sources）
2) 若仍不足且候选 k 尚未扩大 → `expand_candidates`（扩大 vector_k/fts_k）
3) 仍不足则停止，返回当前结果

返回结构中包含 `overfilter.{requested_sources,used_sources,actions,vector_k,fts_k,min_needed}`，便于排查“为什么候选不足”。

### 4) fallback 行为存在且可被上层使用
`query_project` 在 pgvector/hybrid 异常时会回退到 chroma 路径，并在返回结构中填充 `fallback`（用于调试可视化）。
