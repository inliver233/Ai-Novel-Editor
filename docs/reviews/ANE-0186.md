# ANE-0186 — 模式门槛（写死，避免执行期分叉）

本条用于把 Epic 4.2 的“模式门槛/禁止分叉”落实到代码路径，避免出现“不安全但仍继续用旧库检索”的隐式模式。

## Phase 1 强制策略
- 默认只使用 per-project 向量库：`<project_path>/.rag/vectors.db`（由 `IndexScheduler` 监听 `Shared.projectChanged` 触发切换）。
- 启动时不创建/不绑定旧版全局向量库（`src/main.py` 仅初始化 `RAGService`，`vector_store` 延后在项目打开后绑定）。
- 禁用 RAG 作为安全退路：不做检索/不做索引，且不会继续用旧全局库检索。

## 迁移门槛（Option C）
- 迁移仅在满足“可可靠识别当前项目归属”时开放；否则按钮置灰并给出原因。
- 方案 B（表内 `project_id` 过滤）是必要前提：`document_embeddings.project_id` + 所有读写强制 `WHERE project_id = ?` 过滤。

## 代码落点
- `src/main.py`：RAGService 初始化但不创建 legacy 全局 `vectors.db`。
- `src/gui/services/index_scheduler.py`：
  - `Shared.projectChanged` → per-project vectors 解析/切换与 A/B/C 分支
  - `_disable_rag()`：禁用路径（清引用 + 取消 `rag/*` 任务 + 跳过后续调度）
  - `_migrate_legacy_vectors_db()`：仅迁移可确认归属于当前项目的 legacy 条目（基于 `document_id` 路径）
- `src/core/sqlite_vector_store.py`：`project_id` 列 + 强制 project_id 过滤（写入/查询/清理）。
