# ANE-0173 — EPIC 4.2：embedding 兼容与重建策略（闭环）

本 Epic 的目标是：在不破坏现有行为/兼容性的前提下，明确并落实 “vectors.db 按项目隔离 + 首次切换重建/禁用/迁移策略 + 隐私护栏”。

## 已落地的关键约束（写死）
- **默认方案（Phase 1）**：每项目独立向量库：`<project_path>/.rag/vectors.db`。
- **旧全局库仅用于检测/提示**：`~/.ai-novel-editor/vector_store/vectors.db` 不再作为检索数据源继续使用。
- **首次切换策略（A/B/C）**：
  - A：重建索引（默认/推荐，后台任务，可取消）
  - B：禁用 RAG（不检索/不索引；不使用旧全局库）
  - C：迁移（仅当能可靠识别归属时才启用；否则置灰并提示原因）
- **稳定实例策略**：`RAGService` 实例保持稳定，项目切换时仅替换其内部 `vector_store`（并刷新必要缓存引用）。

## 代码落点
- `src/core/vector_store_paths.py`：统一解析 per-project vectors 路径 + legacy 全局路径。
- `src/gui/services/index_scheduler.py`：监听 `Shared.projectChanged` 并执行：
  - per-project `SQLiteVectorStore` 创建/绑定
  - legacy 检测 + 首次切换弹窗（A/B/C）
  - 禁用路径（取消 `rag/*` + 清引用 + 跳过调度）
  - 元数据不兼容提示（重建/禁用）
- `src/main.py`：启动时创建 `RAGService` 但不创建/绑定 legacy 全局 vectors.db。
- `src/core/sqlite_vector_store.py`：`document_embeddings.project_id` + 强制 `WHERE project_id = ?` 过滤（防跨项目读写）。
- `src/gui/ai/enhanced_ai_manager.py`：监听 `projectChanged` 并刷新 context_builder 缓存引用，避免旧引用继续指向老对象。

## 验收方式
### 自动化（覆盖隐私护栏核心）
- `tests/test_epic_4_2_project_isolation.py`：在同一 `vectors.db` 内写入两个不同 `project_id` 的 embeddings，验证查询/删除不会跨项目返回或影响对方。

### 手工（覆盖 UI/交互）
1) 准备两个项目 A/B（内容不同）。
2) 依次打开 A、建立索引；打开 B、建立索引。
3) 在 A 中执行检索：结果只来自 A；在 B 中执行检索：结果只来自 B（可用 `document_id` 路径/前缀验证）。
4) 若本机存在旧版全局库且包含 embeddings：首次打开新项目时应弹出 A/B/C 选择弹窗；选择 B 后应明确进入 “RAG 未启用/禁用” 状态且不再检索旧库。
