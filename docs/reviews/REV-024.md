# REV-024 — Style Profiles CRUD / project default 权限 review

## 背景
Style Profiles（WritingStyle）为用户资产（user-owned）或系统预设（preset），并可在项目维度设置默认 style（ProjectDefaultStyle）。
本条目审计：
- `/api/writing_styles*` 的 ownership/只读边界
- `/api/projects/{project_id}/writing_style_default` 的 RBAC 与 style_id 越权校验
- prompt_content 的边界（防止超大 payload / 注入异常）

## 检查项
- user style：仅 owner 可改/删，且不允许改/删 preset
- preset：可读不可写
- project default：仅 project editor 可读/写；写入时校验 style_id 是否可用
- prompt_content：schema 限制与存储边界（Text 字段）

## 发现点
### 1) WritingStyle ownership 边界明确
- `GET /writing_styles`：只返回 `owner_user_id == user_id` 的非 preset styles
- `POST/PUT/DELETE /writing_styles/{id}`：
  - `_require_owned_user_style` 要求 `!is_preset && owner_user_id == user_id`
  - 非 owner / preset 统一返回 not_found（避免枚举）

### 2) Project default 权限与越权校验到位
- `GET/PUT /projects/{project_id}/writing_style_default`：均要求 `require_project_editor`
- PUT 时若 `style_id != null`：
  - style 必须存在
  - 若 style 非 preset，必须 `owner_user_id == user_id`，否则 403（阻断“引用他人 style”越权）

### 3) prompt_content 边界（建议作为契约/校验项持续关注）
- DB 字段为 `Text`，需要依赖 schema 层限制避免异常超大内容（前端也有 textarea 输入）。
- 当前 UI 会在列表中直接展示 prompt_content（`<pre>` 文本渲染，React 自动转义，XSS 风险低）。

## 结论
Style Profiles 的 ownership/只读边界与 project default 的越权校验总体正确；前端渲染为纯文本，安全性良好。

## 缺口与建议（不在本次实现范围内）
- 增加 API contract 测试覆盖：
  - 非 owner 不能设置他人自定义 style 为项目默认（应 403）
  - prompt_content 的最大长度边界（应 400）
- 若希望 viewer 也能“查看项目默认 style”，可评估将 default 的 GET 权限下放到 viewer（需要同步 UI/产品预期）。
