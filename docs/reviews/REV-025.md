# REV-025 - [feature][style] style_id 注入与 post_edit 流水线 review

## 背景
本条目审计两块链路：

1) `style_id` → `style_guide` 的解析与权限边界（避免越权读取他人风格内容）  
2) `post_edit` 流水线：preset 注入、输出验证、失败回退，以及是否在 LLM 调用期间持有长事务

范围以 CSV `Files` 为准：
- `backend/app/services/style_resolution_service.py`
- `backend/app/services/generation_pipeline.py`
- `backend/app/resources/prompt_presets/post_edit_v1/*`

## 检查项
- `style_id` 不存在/越权时是否拒绝
- project 默认 style 的权限边界是否一致
- `post_edit` preset 是否正确注入 `style_guide`，并具备 sanitize 开关
- `post_edit` 输出是否做结构/长度验证，失败时是否可回退且 warning 可解释
- LLM 调用是否在 DB session 外执行（避免长事务）

## 发现点
### 1) style_id 权限与 fallback 逻辑（OK）
`resolve_style_guide()` 的决策顺序为：
`request(style_id)` → `project_default(style_id)` → `settings_style_guide` → empty。

- 显式传入 `requested_style_id` 时：
  - 不存在：`validation` 错误（“style_id 不存在”）
  - 存在但非 preset 且非本人拥有：`forbidden`（“无权限使用该风格”）
- project 默认 style：同样会做 `_can_use_style` 校验，避免“项目默认指向他人私有风格”造成越权注入
- `include_style_guide=false` 时直接返回空（source=disabled）

结论：`style_id` 注入链路对“越权使用他人私有风格”有明确拦截。

### 2) post_edit：不持有长事务（OK）
`run_post_edit_step()` 在 `with SessionLocal() as db:` 内仅做：
- `ensure_default_post_edit_preset(...)`
- 构建 render values
- `render_preset_for_task(...)`

随后立即退出 `with` 块，再执行 `call_llm_and_record(...)`。

结论：LLM 调用不持有 DB session（满足“不持有长事务”的约束）。

### 3) post_edit：preset 注入、输出验证与失败回退（OK）
`post_edit_v1` preset 的关键点：
- system：`sys.post_edit.role`（硬规则 + `<rewrite>` 输出约束）
- system：`sys.post_edit.sanitize`（可选块：`post_edit_sanitize=true` 时启用）
- system：`sys.project.style_guide`（`style_guide` 存在时注入到 `<STYLE_GUIDE>...</STYLE_GUIDE>`）
- user：`user.post_edit.input`（`<RAW_CONTENT>...</RAW_CONTENT>`）

`run_post_edit_step()` 的结果判定：
- 先走 output contract parse（收集 parse warnings / parse_error）
- `content_md` 为空、parse_error 非空、或 `validate_post_edit_output(...)` 返回 warnings 时：`applied=False`
- `applied=False` 时追加 `post_edit_failed`，以保证“失败回退”可被上层识别且原因可解释（warnings 列表）

结论：post_edit 有明确的“输出验证 + 不可用即失败回退”语义，并能通过 warnings 解释失败原因。
