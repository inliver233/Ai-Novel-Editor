# REV-013 — annotations fallback 与 ChapterAnalysisPage 高亮 review

## 背景
本条目聚焦两块：
1) 后端 `annotations_service.apply_position_fallback` 的定位兜底逻辑（长文/截断场景的可靠性）。
2) 前端 ChapterAnalysis 页面高亮渲染（重叠标注/分段算法/性能与边界）。

目标：给出可复核的审计结论；若发现风险点则做最小修复并补测试。

## 检查项
- 后端
  - span 合法性判定是否基于全文长度，而非被截断的扫描窗口
  - fallback 搜索窗口截断（`max_scan_chars`）是否会导致“有效标注被误判无效”
  - fallback 成功/失败时对 `position/length` 与 `metadata.position_fallback` 的写入是否一致
- 前端
  - `buildAnnotatedTextSegments` 对重叠标注的分段是否正确（含 primary 选择）
  - invalid annotation（position/length 不合法）是否会污染高亮渲染
  - 长文/多标注的算法复杂度与可接受性

## 发现点
### 1) 后端：长文截断会误判“有效 span”为无效（已修复）
`apply_position_fallback` 先将 `content_md` 截断到 `max_scan_chars`（默认 20000）作为搜索文本，然后用**截断后的长度**去校验 annotation 的 `position/length` 是否有效。

这会导致：当章节正文超过 20000 字符且某条标注位置落在 20000 之后时，即使该 span 对**全文**是合法的，也会被视为无效并进入 fallback；而 fallback 的搜索文本又不包含 20000 之后的内容，最终该标注可能被清零为 `position=-1,length=0`，从而在前端被过滤掉/无法高亮。

修复：将 span 合法性校验基准改为全文长度（`len(content_md)`），仅在需要 fallback 时仍使用截断的 `search_text` 做搜索；并新增单测覆盖该长文场景。

### 2) 前端：高亮分段算法覆盖重叠与邻近分组（无需改动）
- `ChapterAnalysisPage` 会先按正文长度过滤 `validAnnotations`，确保传给 `AnnotatedText` 的 span 都是合法的。
- `buildAnnotatedTextSegments` 使用事件扫描（start/end events）生成分段，能产生 overlap segment，并用 importance/id 规则选 primary。
- “邻近分组（adjacencyTolerance）导致 gap 也会产出 annotated segment（activeAnnotations 为空）”是**设计行为**，已有单测覆盖。

整体上：重叠处理与 invalid 过滤链路完整；复杂度约 `O(n log n)`（排序 events），在可预期规模下可接受。

## 结论
- 后端：存在长文截断误判风险，已做最小修复并补单测。
- 前端：重叠/邻近分段行为与 invalid 过滤符合当前设计；无需改动。

## 修复方案
- 后端 `apply_position_fallback`：
  - span 合法性校验使用全文长度
  - 保持 fallback 搜索使用截断窗口（性能）
  - 新增单测覆盖 “valid span 落在 scan window 之后” 场景
