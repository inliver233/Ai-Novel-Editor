# REV-026 - [feature][generation] applyRunId race 复盘与防回归 review

## 背景
`writing` 页面通过 `applyRunId`（query param）触发“将某次生成记录应用到编辑器”的流程。

本条目聚焦：
- `useApplyGenerationRun` 是否会在 batch apply 的时序下“提前清理 applyRunId”，导致应用丢失
- `batch-generation` UI spec 是否能覆盖该回归风险（避免误报通过）

范围以 CSV `Files` 为准：
- `frontend/src/pages/writing/useApplyGenerationRun.ts`
- `test/specs/ui/batch-generation.spec.ts`

## 检查项
- applyRunId 清理时机是否安全（尤其是 chapter 切换的 race）
- 回归用例能否在 apply 未生效时可靠失败

## 发现点
### 1) useApplyGenerationRun：对 batch apply 的 race 已有保护（OK）
`useApplyGenerationRun` 默认会在流程结束时清理 `applyRunId`，但对 batch apply 的典型 race 做了显式保护：

- 当拉取到的 `run.chapter_id` 与当前 `activeChapter.id` 不一致时，会设置 `shouldClearApplyRunId=false` 并直接返回
- 注释说明：batch apply 可能在“章节切换完成前”先写入 applyRunId，需要保留参数等待 chapter 切换后重试

结论：对“跨章节 apply 的时序 race”已有防提前清理设计（`shouldClearApplyRunId`）。

### 2) 回归用例补强：避免“apply 未生效但测试仍通过”（FIXED）
原 `batch-generation` spec 用 `toHaveValue(/E2E/)` 检查编辑器内容，但 seed content 同样包含 `E2E`，存在误报通过风险。

本次调整：
- 将 chapter 1 的 seed 文本改为唯一标识 `__SEED_CH1__`
- apply 后断言：
  - 编辑器内容包含 `E2E`（来自 Mock LLM 生成输出）
  - 编辑器内容不再包含 `__SEED_CH1__`（避免仍停留在 seed 状态）

结论：用例现在能在“applyRunId 被提前清理 / apply 未触发 / 应用失败”时更稳定地失败，从而形成防回归。

## 证据（命令与关键输出摘要）
UI/E2E（按 CSV Test_Method）：
- 命令：`cd test; npm test -- specs/ui/batch-generation.spec.ts`
- 结果：1 passed
- 报告：`test/.artifacts/playwright-report/index.html`

## 结论
本条目未修改 `useApplyGenerationRun` 的业务逻辑；通过补强 `batch-generation` 用例的断言，覆盖“applyRunId race 相关回归”的关键风险点。
