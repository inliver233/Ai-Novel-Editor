# REV-011 — [feature][worldbook] WorldBook CRUD trigger injection review

## 背景
- WorldBook（世界书）提供项目级条目，用于生成前注入上下文。
- 本项审计：CRUD 的 RBAC、触发算法（constant/keyword/recursion）与注入格式（包含截断语义）。

## 检查项（Checklist）
- CRUD / RBAC：
  - list / preview 需 viewer
  - create/update/delete 需 editor（或资源级 editor）
- 触发算法：
  - constant 条目是否可选注入
  - keyword 匹配是否大小写无关、是否去重
  - recursion 的 enable/disable 与 exclude/prevent 语义是否清晰
  - recursion 是否有上限防止无限扩散
- 注入格式：
  - 单条与整体 `char_limit` 截断是否生效
  - 条目排序是否稳定（constant/priority/updated_at）
  - 包裹标记（`<WORLD_BOOK>...</WORLD_BOOK>`）与分隔符是否稳定

## 发现点
1) RBAC 边界清晰
- `backend/app/api/routes/worldbook.py`：
  - `GET /projects/{project_id}/worldbook_entries` → `require_project_viewer`
  - `POST /projects/{project_id}/worldbook_entries` → `require_project_editor`
  - `PUT|DELETE /worldbook_entries/{entry_id}` → `require_worldbook_entry_editor`（基于 entry.project_id 做 editor 校验）
  - `POST /projects/{project_id}/worldbook_entries/preview_trigger` → `require_project_viewer`

2) 触发算法为“constant + keyword 子串匹配 + 可选递归扩散”，并具备递归上限
- `backend/app/services/worldbook_service.py::_trigger_entries`：
  - `include_constant`：先注入 `constant=true` 且 `enabled=true` 的条目（reason=`constant`）
  - keyword：对 `keywords_json` 做 lower + 去重，基于 query/search_text 的 **子串包含** 匹配（reason=`keyword:<matched>`）
  - recursion：
    - `enable_recursion=true` 时，把已触发条目的 `content_md` 拼入搜索文本（除非 `prevent_recursion=true`）
    - `exclude_recursion=true` 的条目只在原始 query 上匹配，不使用递归文本
  - `max_passes = max(1, len(pending)+1)`，避免无限循环

3) 注入格式与截断语义明确
- `_format_worldbook_text`：
  - 单条截断：按条目自身 `char_limit` 截断 `content_md`
  - 整体截断：按 request `char_limit` 截断最终拼接文本，并输出 `truncated=true`
  - 排序：constant 优先，其次 priority（must>important>optional），再按 `updated_at` 新→旧
  - 输出包裹：`<WORLD_BOOK>...</WORLD_BOOK>`，条目间以 `---` 分隔

## 边界用例清单（建议）
- keyword 匹配：
  - 空 keywords（不触发）
  - 大小写/重复关键字（去重）
  - 子串误命中（例如 `he` 命中 `the`）——当前是设计取舍，若需要更精确可考虑分词/边界匹配
- recursion：
  - `prevent_recursion=true` 条目不参与递归扩散
  - `exclude_recursion=true` 条目不使用递归文本匹配
- 截断：
  - 单条内容超 `entry.char_limit` 时截断
  - 总拼接超 `request.char_limit` 时截断并 `truncated=true`
