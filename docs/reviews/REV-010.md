# REV-010 — [data][migration] SQLite 到 Postgres 搬运脚本审计

## 背景
- `backend/scripts/migrate_sqlite_to_postgres.py` 用于将 SQLite 数据搬运到 Postgres（保留 id），以支持 `pgvector` 与生产化部署。
- 本项关注：可恢复性（resume）、安全性（dry-run/空库检查）、校验报告（report）、敏感信息处理（URL/密钥/隐私）。

## 检查项（Checklist）
- CLI/参数：
  - 是否提供 `--dry-run`（只规划不写入）
  - 是否提供 `--resume`（幂等断点续跑）
  - 是否支持输出 report（计数/抽样/外键检查）
  - `--target` URL 是否在日志中脱敏
- 安全护栏：
  - 默认是否拒绝向“非空目标库”写入（避免重复导入污染）
  - `--resume` 是否仅在满足条件时启用（例如主键存在）
- 校验：
  - 是否对每表做 source/target count 对齐
  - 是否提供抽样一致性校验（hash）
  - 是否提供外键缺失检查
- 敏感信息：
  - report 是否避免写入明文密钥/大字段内容

## 发现点
1) 参数完备，支持 dry-run / resume / report
- `--dry-run`：只输出计划
- `--resume`：Postgres 下使用 `ON CONFLICT DO NOTHING`（并对“无主键表”显式报错，避免不安全 resume）
- `--report`：写入 JSON 报告（默认 `sqlite_to_postgres.report.json`）

2) 目标 URL 输出已脱敏
- `_mask_db_url(...)` 会将 URL 中 `password` 替换为 `***`，并用于 console 输出与 report。

3) 有默认安全护栏：目标库非空时拒绝写入（除非 resume/dry-run）
- 脚本在非 `--resume` 且非 `--dry-run` 时，会要求目标库为空，避免重复导入造成数据污染。

4) 报告为“计数/抽样 hash/外键缺失总数”，未见写入明文数据
- 抽样使用 `_sample_hash(rows)` 计算哈希，不把抽样 rows 直接落盘。
