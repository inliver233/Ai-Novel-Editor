目标（摘自 `完全重构计划.md:1217`）：

## 已落地能力

1) **安全存储默认启用（避免 `config.json` 明文）**
- `Config.set()/set_section()` 对 `ai.api_key` / `rag.api_key` 写入做拦截：写入安全存储，配置文件中写空字符串。
- 启动迁移：`Config._migrate_api_keys()` 会把旧版明文 key 迁移到安全存储并清空配置字段（含 RAG）。

实现/证据：
- `src/core/config.py`
- `tests/test_secure_storage_defaults.py`
- 关联说明：`docs/reviews/ANE-0302.md`

2) **安全存储实现审计与健壮性增强**
- 输出审计结论与风险/后续建议
- key store 写入采用原子写，读失败可恢复（避免损坏导致无法保存）

实现/证据：
- `src/core/secure_key_manager.py`
- `docs/reviews/ANE-0280.md`

3) **日志脱敏与“敏感大 payload”避免**

- `core.log.configure_logging()` 添加 loguru patcher：对关键模式做文本级脱敏与截断。
- `AIClient` 不再在 debug 日志中输出完整请求 payload（避免 prompt/messages 泄露）。

实现/证据：
- `src/main.py`
- `src/core/log.py`（`redact_sensitive_text`）
- `src/core/ai_client.py`
- `tests/test_log_redaction.py`

4) **配置导出不包含密钥**
- AI 配置方案（import/export）写入 JSON 前统一脱敏：`api_key`/`Authorization`/相关 header 字段置空。

实现/证据：

## 手工验收建议（补齐 “启动一次应用后扫日志”）

由于自动化环境无法完整模拟 GUI 操作链路，建议在本机进行一次手工验收：

1) 启动应用（建议 `log_level=DEBUG`）并触发一次 AI + RAG  
2) 检查 `~/.ai-novel-editor/logs/` 下日志文件，确认不包含：
   - `api_key`、`sk-`、`Bearer `、`x-api-key`、`x-goog-api-key`
3) 检查 `config.json` 不包含明文 key（字段为空或不存在）
