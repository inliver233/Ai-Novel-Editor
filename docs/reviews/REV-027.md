# REV-027 - [quality][tests] Playwright 稳定性与 flaky 排查

## 背景
本条目目标是对 `test/`（Playwright 黑盒测试）做一次稳定性审计：
- 运行全套用例，确认当前回归是否稳定
- 复盘常见 flaky 来源（选择器、时序、对话框、流式生成）
- 输出可执行的修复/加固建议（必要时更新文档）

范围以 CSV `Files` 为准：`test/specs/* | test/lib/* | test/README.md`

## 检查项
- 选择器：优先 `getByRole/getByLabel`，尽量 `exact: true`，避免包含匹配带来的 strict-mode 偶发
- 时序：避免对“流式生成/异步渲染”使用脆弱的固定等待；用可观测状态（visible/text/value）驱动
- 对话框：dirty confirm / leave confirm 等是否有兜底处理，避免残留弹窗导致后续点击失败
- 产物：失败时是否自动落 trace.zip / screenshot / video，便于复现与定位

## 发现点
### 1) 本次全套回归未观测到 flaky（PASS）
本轮执行全套 `npm test`，49/49 通过，未产生失败用例的 trace 产物。

### 2) 潜在 flaky 热点（风险提示）
虽然本次未失败，但以下类别天然更容易抖动，建议持续关注：
- **流式生成/回退链路**：如 `chapter-stream*.spec.ts`、`outline-stream*.spec.ts`（UI 渲染与后端 SSE 交互）
- **多弹窗分支**：如 `writing-unsaved-confirm.spec.ts`、`batch-generation.spec.ts`（弹窗出现与否受状态影响，需保证每条分支都能闭环）
- **视觉回归**：`visual.spec.ts`（字体/动画/布局抖动；已在 README 中给出 mask/禁动等策略）

加固建议（优先级从高到低）：
1) 关键点击前先断言 `toBeVisible()`，并尽量用 `exact: true`（避免误点/点击到同名按钮）
2) 对话框处理：用“显式 wait + 条件点击”替代大范围 try/catch（减少隐藏问题）
3) 对长耗时操作统一使用“可观测结果”等待（例如 textarea value / toast / 某个关键文案出现），不要用固定 sleep
