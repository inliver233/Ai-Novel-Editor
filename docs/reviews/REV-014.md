# REV-014 — MemoryContextPack 与 ContextPreviewDrawer review

## 背景
`/api/projects/{project_id}/memory/retrieve` 用于提供写作页“上下文预览”所需的 `MemoryContextPack`（Phase 0：允许为空，但顶层结构必须稳定），并要求在缺少 embedding / vector DB / 相关依赖时依旧 **fail-soft**（可返回 disabled_reason/空结构，而不是直接报错）。

本条目审计：
- 后端 `memory/retrieve` 的输出结构与 `pack.logs` 语义
- 前端 `ContextPreviewDrawer` 对 pack 的解析与“世界书注入开关”的一致性

## 检查项
- 后端
  - 输出是否始终包含稳定的顶层 keys（避免前端判空/渲染崩溃）
  - `pack.logs` 是否用于说明各 section 的 enabled/disabled_reason/下一步指引
  - 缺失依赖时是否走 fail-soft（返回 disabled_reason 或空，而不是抛异常）
- 前端
  - 注入开关关闭时是否避免触发 retrieve 请求，并且 UI 文案/空包展示一致
  - 开关开启时是否加载 pack，并用 raw pack 视图暴露 logs（便于排查）

## 发现点
### 1) 输出结构稳定（符合 Phase 0 合约）
- `MemoryContextPackOut` 定义了稳定顶层 shape：`worldbook/story_memory/structured/vector_rag/graph/fractal/logs`，均提供 default_factory（空 dict / 空 list）。
- `GET /memory/retrieve` 直接返回 `pack.model_dump()`，保证即使各 section 尚未实现，也能返回稳定结构（契约测试覆盖）。

### 2) pack.logs 的当前语义：面向调试的“section 状态摘要”
- `retrieve_memory_context_pack` 会为 `vector_rag` 与 `fractal` 追加 log，包含：
  - `section`
  - `enabled`
  - `disabled_reason`
  - `note`（指向后续 phase 的可操作 endpoint）
- 前端未对 logs 做结构化渲染，但提供 “raw pack JSON” 视图，可用于排查（含 logs）。

### 3) 注入开关与请求/展示一致（fail-soft 友好）
- drawer 打开且注入开启时触发 `load()` 拉取 pack。
- 注入关闭时：不触发请求，并主动清空 pack/error/requestId，且 `effectivePack` 固定回到 EMPTY_PACK，避免旧数据污染 UI。

## 证据（命令与关键输出摘要）
- 代码审计：
  - `backend/app/schemas/memory_pack.py`
  - `backend/app/services/memory_retrieval_service.py`
  - `backend/app/api/routes/memory.py`
  - `frontend/src/components/writing/ContextPreviewDrawer.tsx`
- 验收测试按 CSV Test_Method 执行（见下方“测试结果”）

## 结论
当前实现满足 Phase 0 的“稳定结构 + fail-soft”目标；`pack.logs` 的语义清晰且通过 raw pack 暴露给前端排查。无需代码改动。

## 修复/改进建议（不在本次实现范围内）
- 为 `pack.logs` 引入更明确的 schema（例如 `section/enabled/disabled_reason/note` 的 Pydantic model），并在前端做更友好的摘要展示（减少只能看 raw JSON 的成本）。
- 对 `worldbook/vector_rag/fractal` 等 section 统一补齐 `enabled/disabled_reason` 的 contract（当前仅部分 section 包含该语义）。
