# REV-005 — [security][injection] SQL text 与 Prompt template 注入面审计

## 背景
- 本项关注两类“注入面”：
  1) SQLAlchemy `text(...)`：若拼接用户输入到 SQL 字符串，可能产生 SQL 注入。
  2) Prompt 模板渲染：若模板引擎允许执行任意表达式/代码，可能形成代码执行或越权读取（模板注入）。

## 检查项
- SQL：`text(...)` 是否仅用于固定 SQL + 参数绑定；是否存在把 user input 拼入 SQL 字符串的情况。
- 模板：模板渲染是否为“安全子集”（只做变量替换/受限 if），是否存在 `eval/exec` 等危险行为。
- 资源：`backend/app/resources/prompt_presets/*` 是否为静态资源（不来自用户输入）。

## 发现点
1) `vector_rag_service.py` 的 `text(...)` 使用为“固定 SQL + 参数绑定”，注入风险低
- 表名 `_PGVECTOR_TABLE` 为常量（`"vector_chunks"`）。
- where 条件由固定片段拼接（`project_id = :project_id` + `source = :source/ANY(:sources)`），未见直接拼入用户可控文本。
- 查询文本 `qtext`、向量 `qvec`、ids/sources 等均通过命名参数传入。

2) Prompt 模板渲染为自研安全子集，不执行任意表达式（无模板注入到代码执行）
- `prompt_presets.py` 使用 `app.services.prompting.render_template(...)` 渲染 block.template。
- `prompting.py` 的 `_render_safe_template`：
  - 仅支持 `{{ safe.path }}` 变量路径替换 + `{% if ... %}` 的受限表达式（自写 parser）。
  - 不支持任意函数调用；不使用 `eval/exec`。
  - 对不支持的 `{{ ... }}` 表达式保持原样输出（不会求值）。

3) `backend/app/resources/prompt_presets/*` 为本地静态资源
- 作为“默认预设模板”来源，不直接接收外部用户输入（用户只能通过 Prompt Studio 写入 DB 的 prompt blocks；仍由安全模板渲染处理）。

## 证据（命令与关键输出摘要）
- `rg -n "text\\(" backend/app/services/vector_rag_service.py -S`
  - `vector_rag_service.py:301/416/425/453`（固定 SQL + 命名参数）
- `rg -n "render_preset_for_task|render_template" backend/app/services/prompt_presets.py backend/app/services/prompting.py -S`
  - `prompt_presets.py` 调用 `render_template`
  - `prompting.py` 自研 parser（无 `eval/exec`）

## 结论
- 未发现明确的 SQL 注入或“模板注入导致代码执行”的高风险问题。
- 仍需注意：Prompt 注入（对 LLM 的指令污染）属于产品层风险，不等同于后端代码执行；应通过输出契约/后处理/工具隔离等策略缓解（不在本 issue 改动范围内）。
