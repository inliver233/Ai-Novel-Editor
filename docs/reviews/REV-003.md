# REV-003 — [security][rbac] /api 越权 IDOR 全量审计

## 背景
- 后端大量资源以 `project_id` 作为租户边界；若路由对 `project_id`/资源 `id` 缺少校验，容易出现跨项目访问（IDOR）。
- 本次目标：逐路由确认是否存在“未校验项目成员关系/角色”的读写入口。

## 检查项（Checklist）
- 是否要求登录（`UserIdDep` / `AuthenticatedUserIdDep`）或明确允许匿名（如 `/health`）。
- `projects/{project_id}/...`：是否调用 `require_project_viewer/editor/owner`。
- `/{resource_id}`：是否调用 `require_*_viewer/editor` 并基于资源的 `project_id` 做成员校验。
- 资源级隔离：当路径同时包含 `project_id` 与资源 `id` 时，是否校验二者一致（防拼接绕过）。

## 发现点（结论先行）
- `backend/app/api/deps.py` 提供了统一的 project/资源级鉴权函数（viewer/editor/owner），多数路由均按约定调用。
- 本次抽查所有 `backend/app/api/routes/*` 的路由定义，未发现“缺少 project 成员校验导致跨项目读写”的明确漏洞。
- 兼容性/信息泄露层面：多数跨项目访问会返回 `403 FORBIDDEN`（意味着可能泄露资源存在性）；少数“路径带 project_id 且二者不一致”的场景使用 `404 NOT_FOUND`（更偏 fail-closed）。该差异本次仅记录为观察点，未做行为变更。

## 证据（命令与关键输出摘要）
- 路由枚举：
  - `rg -n "^@router\\.(get|post|put|delete)\\(" backend/app/api/routes -S`
- 统一鉴权实现：
  - `backend/app/api/deps.py`：`require_project_viewer/editor/owner` + `require_*_viewer/editor`（基于资源 `project_id` 做成员校验）

## 逐路由 Checklist（按 routes 文件）

### auth.py
- `GET /auth/user`：`AuthenticatedUserIdDep`（必须真实登录；dev fallback 无法访问）
- `POST /auth/local/login`：匿名可用（设置 session cookie）
- `POST /auth/password/change`：`AuthenticatedUserIdDep`
- `POST /auth/admin/users/{target_user_id}/disable`：`AuthenticatedUserIdDep` + `actor.is_admin`
- `POST /auth/refresh`：`AuthenticatedUserIdDep`
- `POST /auth/logout`：匿名可用（清 cookie）

### health.py / llm_capabilities.py
- `GET /health`：匿名可用（健康检查）
- `GET /llm_capabilities`：匿名可用（纯计算能力表，不涉及用户/项目数据）

- `GET /projects/summary`：`UserIdDep`（仅汇总 owner/member 项目数据）
- `POST /projects`：`UserIdDep`（创建项目，owner=当前 user）
- `GET /projects/{project_id}`：`require_project_viewer`
- `PUT /projects/{project_id}`：`require_project_owner`（并校验 `active_outline_id` 属于该 project；`llm_profile_id` 必须 owned）
- `DELETE /projects/{project_id}`：`require_project_owner`
- `GET /projects/{project_id}/settings`：`require_project_viewer`
- `PUT /projects/{project_id}/settings`：`require_project_editor`
- `GET /projects/{project_id}/export/markdown`：`require_project_viewer`

- `POST /projects/{project_id}/characters`：`require_project_editor`

## 修复方案
- 本次未发现必须立刻修复的越权/IDOR 漏洞，因此未做代码修改。
- 后续如需进一步降低“资源存在性泄露”，可评估将部分 `FORBIDDEN` 场景改为 `NOT_FOUND`（需要统一错误语义与补充契约测试，建议另起 issue）。
