# REV-012 — [feature][analysis] plot_analysis apply 幂等与 story_memories 一致性 review

## 背景
- `analysis/apply` 会将章节分析结果落库为 `plot_analysis` 与派生的 `story_memories`，并写入 `generation_runs` 作为审计记录。
- 本项关注：
  - 幂等：相同 analysis 重复 apply 不应重复写入/产生重复 memories；
  - 一致性：managed memory types 的覆盖/清理策略是否正确；
  - 审计：是否有可追溯的 GenerationRun 记录与 hash 口径。

## 检查项
- 哈希口径：analysis canonicalization 是否稳定（字段顺序/空值/类型）。
- 幂等判定：重复 apply 是否直接返回既有记录（`idempotent=true`）。
- 覆盖策略：仅清理/重建受管的 `StoryMemory.memory_type`，不误删其它来源的 memories。
- 审计记录：是否写入 `GenerationRun(type="analysis_apply")` 并记录 `analysis_hash`。

## 发现点
1) 幂等口径：以 canonical JSON 的 sha256 作为 analysis_hash
- `plot_analysis_service.compute_analysis_hash(...)` 生成 canonical_json + hash。
- `apply_chapter_analysis`：
  - 若已有 `PlotAnalysis` 且 `sha256(existing.analysis_json) == analysis_hash` → 直接返回已有 memories（`idempotent=true`）。

2) managed types 覆盖策略明确
- `_MANAGED_MEMORY_TYPES`：`chapter_summary/hook/plot_point/foreshadow/character_state`
- 非幂等路径会先删除该 chapter 下上述类型的旧 `story_memories`，再按 seeds 重建（避免重复/漂移）。

3) GenerationRun 审计记录存在
- apply 成功时写入 `GenerationRun(type="analysis_apply")`，并在 `params_json` 记录 `analysis_hash`，便于追踪。

## 一致性风险点（建议关注）
- analysis 输入为“开放 dict”时：
  - 若上游契约字段变更/缺失，canonicalization 可能导致 hash 变化，从而触发非幂等覆盖（需要契约测试/版本化策略兜底）。
- managed types 列表为硬编码：
  - 新增 memory_type 时需同步更新 `_MANAGED_MEMORY_TYPES`，否则可能出现“旧类型未清理”或“新类型不受管”。
