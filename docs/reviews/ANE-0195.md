# ANE-0195 — Phase 1 默认策略：RAGService 实例保持稳定，仅替换内部 vector_store

Phase 1 策略：`RAGService` 实例在进程生命周期内保持稳定；项目切换时只替换其内部持有的 `vector_store`，避免旧引用/旧对象继续指向过期向量库。

## 写死的传播路径
1) 启动时创建 `RAGService` 并挂到 `shared.rag_service`（不依赖 vectors.db 的具体路径）。
2) 项目打开/切换后（`Shared.projectChanged(project_path)`）：
   - 创建/切换到 per-project `SQLiteVectorStore(<project>/.rag/vectors.db)`
   - 更新 `shared.vector_store`
   - 调用 `shared.rag_service.set_vector_store(new_store)`（不新建 `RAGService`）
3) 对已创建的上层对象（如 context_builder）按需刷新缓存引用，避免继续使用老引用。

## 代码落点
- `src/main.py`：创建并设置 `shared.rag_service`（vector_store 延后绑定）。
- `src/gui/services/index_scheduler.py`：在 `projectChanged` 中创建 per-project `SQLiteVectorStore` 并调用 `rag_service.set_vector_store(new_store)`。
- `src/gui/ai/enhanced_ai_manager.py`：监听 `projectChanged` 并刷新 `context_builder` 对 `shared.*` 的缓存引用（防止旧引用继续生效）。
