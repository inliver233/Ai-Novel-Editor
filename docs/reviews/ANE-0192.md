# ANE-0192 — `projectChanged` handler responsibilities

Phase 1 约束：`Shared.projectChanged` 由单一来源触发（见 `docs/reviews/ANE-0190.md`），并由单一监听方（IndexScheduler）收敛“向量库切换/迁移/重建”决策。

## 写死的处理步骤（Phase 1）
当 `Shared.projectChanged(project_path)` 触发时：
1) 解析 per-project vectors 路径：`<project_path>/.rag/vectors.db`
2) 检测旧全局库与新库存在性（旧库要求“确有 embeddings”，避免空库误触发）
3) 必要时弹窗询问（A/B/C）
4) 根据选择设置 `shared.vector_store` 与 `shared.rag_service` 的工作模式，并触发后台重建/或禁用 RAG

## 实现落点
- `src/gui/services/index_scheduler.py`
  - `_on_project_changed()`：执行存在性检测、弹窗与分支调度
  - `_ensure_vector_store()`：Phase 1 默认策略：创建 `SQLiteVectorStore(<project>/.rag/vectors.db)` 并调用 `rag_service.set_vector_store(new_store)`
  - `_disable_rag()`：禁用路径（清空引用 + 取消 `rag/*` 任务 + 后续跳过索引）
  - `schedule_rebuild()`：后台 `rag/rebuild` 任务（可取消）
